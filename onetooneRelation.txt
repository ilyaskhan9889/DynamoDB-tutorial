What “one-to-one” means (plain English)

👉 One user has exactly one profile
Not more, not less.

Example:
User: Ilyas
Profile: Bio, avatar

Key DynamoDB idea (IMPORTANT)
DynamoDB does NOT use tables + joins like MySQL.

Instead:
We use ONE table
We store related items together


Step 1: Think in terms of KEYS only

Every item in DynamoDB must have:
Partition Key (PK) → groups related data
Sort Key (SK) → differentiates items inside the group

Step 2: One-to-One trick (THIS IS THE CORE)

We do this:
| Item    | PK       | SK        |
| ------- | -------- | --------- |
| User    | `USER#1` | `USER`    |
| Profile | `USER#1` | `PROFILE` |


Same PK → they belong together
Different SK → they are different things

That’s it. That’s the relationship.


Step 3: Create the table (once)

aws dynamodb create-table \
  --table-name Users \
  --attribute-definitions \
    AttributeName=PK,AttributeType=S \
    AttributeName=SK,AttributeType=S \
  --key-schema \
    AttributeName=PK,KeyType=HASH \
    AttributeName=SK,KeyType=RANGE \
  --billing-mode PAY_PER_REQUEST \
  --endpoint-url http://localhost:8000

Step 4: Insert the USER

aws dynamodb put-item \
  --table-name Users \
  --item '{
    "PK": {"S": "USER#1"},
    "SK": {"S": "USER"},
    "name": {"S": "Ilyas"}
  }' \
  --endpoint-url http://localhost:8000


Meaning:
This item represents the user


Step 5: Insert the PROFILE (linked automatically)

aws dynamodb put-item \
  --table-name Users \
  --item '{
    "PK": {"S": "USER#1"},
    "SK": {"S": "PROFILE"},
    "bio": {"S": "Backend developer"}
  }' \
  --endpoint-url http://localhost:8000

Meaning:
This item represents the profile of the SAME user

Notice:
Same PK = USER#1
Different SK



Step 6: Read User + Profile (THIS IS THE MAGIC)
aws dynamodb query \
  --table-name Users \
  --key-condition-expression "PK = :pk" \
  --expression-attribute-values '{
    ":pk": {"S": "USER#1"}
  }' \
  --endpoint-url http://localhost:8000


What this does:
“Give me EVERYTHING related to USER#1”

Output:
User item
Profile item

🔥 One query → no JOIN

Visual picture (VERY IMPORTANT)
PK = USER#1
│
├── SK = USER     → name = Ilyas
└── SK = PROFILE  → bio = Backend developer


That’s one-to-one in DynamoDB.
