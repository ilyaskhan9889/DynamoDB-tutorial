Many-to-Many Relationship

Example:
Users ↔ Groups
A user can join many groups
A group can have many users

Step 1: Understand the DynamoDB approach

Unlike MySQL (with a join table), in DynamoDB we store all relationships in one table and design it based on access patterns.
Access patterns we want:
Get all groups a user belongs to ✅
Get all users in a group ✅

Step 2: Table design

Table: UserGroups
Attribute	Purpose
PK	Partition Key (depends on query)
SK	Sort Key (depends on query)
role	Optional: admin/member
joinedAt	timestamp

Two access patterns:

PK = USER#<id>, SK = GROUP#<id> → list groups for a user
PK = GROUP#<id>, SK = USER#<id> → list users in a group

✅ This is called inverted indexing, a common DynamoDB trick for many-to-many.

Step 3: Create table (CLI)
aws dynamodb create-table \
  --table-name UserGroups \
  --attribute-definitions \
    AttributeName=PK,AttributeType=S \
    AttributeName=SK,AttributeType=S \
  --key-schema \
    AttributeName=PK,KeyType=HASH \
    AttributeName=SK,KeyType=RANGE \
  --billing-mode PAY_PER_REQUEST \
  --endpoint-url http://localhost:8000

Step 4: Insert a user-group relationship
Example:

User USER#1 joins GROUP#A

Pattern 1: For user → groups

aws dynamodb put-item \
  --table-name UserGroups \
  --item '{
    "PK": {"S": "USER#1"},
    "SK": {"S": "GROUP#A"},
    "role": {"S": "member"},
    "joinedAt": {"N": "1700000001"}
  }' \
  --endpoint-url http://localhost:8000


Pattern 2: For group → users

aws dynamodb put-item \
  --table-name UserGroups \
  --item '{
    "PK": {"S": "GROUP#A"},
    "SK": {"S": "USER#1"},
    "role": {"S": "member"},
    "joinedAt": {"N": "1700000001"}
  }' \
  --endpoint-url http://localhost:8000


✅ Now both access patterns are possible.

Step 5: Query groups for a user
aws dynamodb query \
  --table-name UserGroups \
  --key-condition-expression "PK = :pk" \
  --expression-attribute-values '{
    ":pk": {"S": "USER#1"}
  }' \
  --endpoint-url http://localhost:8000


Output:

GROUP#A, GROUP#B, etc.

Step 6: Query users in a group
aws dynamodb query \
  --table-name UserGroups \
  --key-condition-expression "PK = :pk" \
  --expression-attribute-values '{
    ":pk": {"S": "GROUP#A"}
  }' \
  --endpoint-url http://localhost:8000


Output:

USER#1, USER#2, etc.

Step 7: Delete a membership

Suppose USER#1 leaves GROUP#A

aws dynamodb delete-item \
  --table-name UserGroups \
  --key '{
    "PK": {"S": "USER#1"},
    "SK": {"S": "GROUP#A"}
  }' \
  --endpoint-url http://localhost:8000

aws dynamodb delete-item \
  --table-name UserGroups \
  --key '{
    "PK": {"S": "GROUP#A"},
    "SK": {"S": "USER#1"}
  }' \
  --endpoint-url http://localhost:8000


Always delete both patterns to keep data consistent

✅ Key Takeaways

DynamoDB does not join tables
Many-to-many → duplicate items for different access patterns
PK + SK design is everything
Query is always by PK (very fast)

Visual Picture
USER#1
 ├─ SK=GROUP#A
 └─ SK=GROUP#B

GROUP#A
 ├─ SK=USER#1
 └─ SK=USER#2
