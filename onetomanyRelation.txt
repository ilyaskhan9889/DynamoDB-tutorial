One-to-Many Relationship in DynamoDB

Example:
One user can send many messages
Each message belongs to exactly one user

This is a classic chat messages table scenario.

Step 1: Table Design

Table: Messages

Attribute	Type	Purpose
PK	S	Partition Key → USER#<id>
SK	N	Sort Key → timestamp of message
message	S	Message text
receiverId	S	Optional: recipient
status	S	read/unread, etc.

Why this works:

All messages for a single user are under the same PK
Sorted by timestamp (SK) → easy to fetch latest messages first
One user → many messages

Step 2: Create Table
aws dynamodb create-table \
  --table-name Messages \
  --attribute-definitions \
    AttributeName=PK,AttributeType=S \
    AttributeName=SK,AttributeType=N \
  --key-schema \
    AttributeName=PK,KeyType=HASH \
    AttributeName=SK,KeyType=RANGE \
  --billing-mode PAY_PER_REQUEST \
  --endpoint-url http://localhost:8000


✅ Table created locally

Step 3: Insert Messages
User 1 sends first message
aws dynamodb put-item \
  --table-name Messages \
  --item '{
    "PK": {"S": "USER#1"},
    "SK": {"N": "1700000001"},
    "message": {"S": "Hello there!"},
    "receiverId": {"S": "USER#2"},
    "status": {"S": "sent"}
  }' \
  --endpoint-url http://localhost:8000

User 1 sends second message
aws dynamodb put-item \
  --table-name Messages \
  --item '{
    "PK": {"S": "USER#1"},
    "SK": {"N": "1700000002"},
    "message": {"S": "How are you?"},
    "receiverId": {"S": "USER#2"},
    "status": {"S": "sent"}
  }' \
  --endpoint-url http://localhost:8000

Step 4: Query All Messages for a User
aws dynamodb query \
  --table-name Messages \
  --key-condition-expression "PK = :pk" \
  --expression-attribute-values '{
    ":pk": {"S": "USER#1"}
  }' \
  --scan-index-forward true \
  --endpoint-url http://localhost:8000


scan-index-forward = true → oldest first

scan-index-forward = false → newest first

Output:

[
  { "SK": 1700000001, "message": "Hello there!" },
  { "SK": 1700000002, "message": "How are you?" }
]

Step 5: Query Messages by Time Range

Get messages after timestamp 1700000001:

aws dynamodb query \
  --table-name Messages \
  --key-condition-expression "PK = :pk AND SK > :time" \
  --expression-attribute-values '{
    ":pk": {"S": "USER#1"},
    ":time": {"N": "1700000001"}
  }' \
  --endpoint-url http://localhost:8000


✅ Only returns messages after that timestamp

Step 6: Update Message Status
aws dynamodb update-item \
  --table-name Messages \
  --key '{
    "PK": {"S": "USER#1"},
    "SK": {"N": "1700000001"}
  }' \
  --update-expression "SET status = :s" \
  --expression-attribute-values '{
    ":s": {"S": "read"}
  }' \
  --endpoint-url http://localhost:8000

Step 7: Delete a Message
aws dynamodb delete-item \
  --table-name Messages \
  --key '{
    "PK": {"S": "USER#1"},
    "SK": {"N": "1700000002"}
  }' \
  --endpoint-url http://localhost:8000

✅ Key Takeaways

Partition Key = user → all messages for a user are grouped

Sort Key = timestamp → enables ordering and range queries

Query by PK only → fast & single-digit millisecond latency

One-to-many in DynamoDB is about PK grouping + SK sorting

Visual Picture
PK = USER#1
 ├─ SK = 1700000001 → "Hello there!"
 └─ SK = 1700000002 → "How are you?"

PK = USER#2
 ├─ SK = 1700000003 → "Hi USER1!"
